# Shared invariants

Some values are duplicated across scripts written in different languages (bash,
jq, Lua, prose) because each implementation is independent — no shared library
spans `bin/claudeb`, `bin/statusline.sh`, `bin/worker-pick`, `llm-limits.sh`, the
Hammerspoon renderer, and the docs. When such a value drifts in one place, the
system misbehaves silently. `tests/test_consistency.sh` re-extracts each value
from the live files and fails if any site disagrees with the canonical value
below. This table is the canonical source; the test names it in every failure.

| # | Invariant | Canonical value | Implementation sites |
|---|---|---|---|
| a | Staleness / dim thresholds | five_hour `1800`s, weekly `21600`s, fable `21600`s | `bin/claudeb` `account_data` jq (`is_stale(.five_hour; 1800)` / `.seven_day; 21600` / `.fable; 21600`); `bin/statusline.sh` dim logic (`now - h5_as_of > 1800`, `now - wk_as_of > 21600`, `now - limits_mtime > 21600`); `docs/statusline-contract.md` usage-table prose (`as_of` >1800s / >21600s, mtime >21600s); `hammerspoon/llm-limits.lua` consumes the collector's `.stale` flag rather than a local threshold (`bucket.stale == true`) — it must stay flag-driven, never hardcode a number |
| b | Keychain service formula | `Claude Code-credentials-` + first 8 hex of `shasum -a 256` of the profile path | `bin/claudeb` `keychain_service`; `llm-limits.sh` `claude_subscription_type` |
| c | worker-pick cache line format | `cx<mark><acct>·<model>·<eff> cb<~|@><acct>·<model>·<eff> gx<mark><acct>·<model>·<eff>` (producer printf `cx%s%s·<model>·%s %s·%s·%s gx%s%s·%s·%s`; Codex model comes from `~/.codex/config.toml`, and each vendor account is dynamic) | producer `bin/worker-pick` `write_cache`; consumer `bin/statusline.sh` reads `worker-pick.line.<acct>` verbatim |
| d | Weather HTTP classes | `000`, `429`, `5xx` (`5[0-9][0-9]`) are weather — they never write an auth verdict (`expired`/`revoked`/`auth-failed`) | `bin/claudeb` `probe_weather_failed` case pattern; `bin/claudeb` `oauth_refresh` outcome classification |
| e | OAuth token-endpoint 429 cooldown | `900 * 2^(max(1, strikes)-1)`, capped at `14400`s (4h); a longer vendor `Retry-After` wins | `bin/claudeb` `oauth_backoff_until`; `llm-limits.sh` `claude_stale_cause` |
| f | Token-freeze file semantics | file at `<store>/token-freeze` present = freeze active; a numeric `until` in the past → inactive (auto-resume); a missing / non-numeric `until` → active while the file exists. The active freeze blocks robot paths only; `CLAUDEB_WARM_USER_EXPLICIT=true` exempts the full user invocation and marks its journal entries with `"user":true` | `bin/claudeb` `token_freeze_active` plus user guards and `token_journal`; `llm-limits.sh` `token_freeze_active_at` plus the user-explicit stale-cause guard |
| g | Codex/Gemini base-profile priority | literal profile `main` sorts after every usable dynamically-enumerated non-main account of the same vendor; selection eligibility and within-group ranking stay unchanged. Display-only account lines sort the selected account first, then automatically eligible, soft-skipped, and hard-unreachable bands while preserving selection order within each band | `bin/worker-pick` Codex and Gemini jq selection rankings plus all three vendors' `display_band` render sorts; `bin/codexb` `pick_account` ranking; `share/worker-policy.md` printed policy |
| h | Antigravity review cell invocation mapping | `agy-pro-<effort>` → `--model "Gemini 3.1 Pro (<Effort>)"` with no `--effort` flag for low/high, because every `gemini-3.1-pro*` id misses agy's local catalog and is silently served as Gemini 3.6 Flash; `agy-flash36-<effort>` → `--model gemini-3.6-flash --effort <effort>` for low/medium/high; `agy-flash35-<effort>` → `--model gemini-3.5-flash-<effort>` with no `--effort` flag for low/medium/high; a resolved label that disagrees with the requested cell is recorded as `model_mismatch` and warned about; every Antigravity cell is a `-skill` cell — diff-only agy review is refused in `parse_rater`, so no caller can request one | `bin/review-bench` `AGY_EFFORTS`, `AGY_MODEL_IDS`, and `agy_model_id`; `~/.claude/agents/gemini-worker.md` canonical relay table for worker-supported models; `docs/DIAGNOSTICS.md` review-bench system-map entry |
| i | Gemini worker knobs | required defaults `gemini_model=pro`, `gemini_effort=high`; valid pairs are pro high/low, flash36 high/medium/low, and flash35 high/medium/low (bare `flash` aliases `flash36`); model and effort are passed as separate flags per invariant h except pro, named by its label (`Gemini 3.1 Pro (<Effort>)`), and flash35, whose effort is encoded in the model id (`gemini-3.5-flash-<effort>`); neither passes `--effort` | accepted knobs/default-writing semantics in `~/.claude/commands/worker.md`; routing defaults in `bin/worker-pick`; statusline reads and renders both knobs independently; policy pointer in `share/worker-policy.md` |
| j | Worker spawn pressure gate | `worker-pick --account <vendor>` owns selection: its selected account is allowed below the hard `100`% wall and warned from `85`%; exit `3` and an effective `100`% account are blocked. `95`% is the protective block only when worker-pick is unavailable or fails, and that fallback is always reported | shared `~/.claude/hooks/worker-limit-gate.sh` for claudeb, Codex, and Gemini worker spawns; `bin/worker-pick` account query; `~/.claude/settings.json` has one Agent registration |
| k | Worker account resolution | for every relay, an `ACCOUNT: <name>` brief line wins; otherwise `worker-pick --account claudeb\|codex\|gemini` applies or lapses the vendor pin; exit `3` refuses the launch; only an unavailable/failed query falls back to the direct pin, then `main` for Codex/Gemini, and that fallback is reported. Claude refuses when its fallback pin is empty because `claudeb` requires an explicit profile | `~/.claude/commands/worker.md` pin toggles; `bin/worker-pick` pin routing; `bin/worker-spawn-hook.sh` pending tag; `~/.claude/agents/claudeb-worker.md`, `codex-worker.md`, and `gemini-worker.md` relay launches |
| l | Gemini quota group matching | case-insensitive group label contains `gemini`; exact display-name equality is forbidden | `llm-limits.sh` raw group collection/validation; `bin/worker-pick` normalized account eligibility |
| m | Gemini profile discovery and HOME mapping | account `main` maps to the process base HOME; named accounts are sorted profile directories and map to `<profiles-dir>/<name>` | `share/gemini-accounts.sh`, sourced by `bin/geminib` and `llm-limits.sh` |
| n | Weekly bucket provenance | rate-limit response headers carry NO weekly percentage, so no writer may stamp `origin: "headers"` on `seven_day`; every reader treats such a bucket as unknown (rendered `?`/`-`, never a number) | writers: `bin/claudeb` `merge_headers` (5h only), `bin/statusline.sh` `rl_merge` stamps `origin: "session"` and drops a cached header-origin week; readers: `bin/claudeb` `account_data`, `llm-limits.sh` both claudeb-store and single-account snapshot reads, `bin/statusline.sh` render gate, `bin/worker-pick` cache normalization |
| o | Claude rotation usability presence | `llm-limits.sh` always emits boolean `rotation.usable.general`, `rotation.usable.fable`, and `blocked == (rotation.usable.general \| not)` for every emitted Claude store account, including incomplete, disabled, and unusable snapshots; consumers may rely on those keys being present. `bin/worker-pick` defaults a missing rotation key to `true` only for compatibility with pre-change caches. Two documented weak spots, both fail-open on `fable` and both bounded by the worker's own `CLAUDEB_USAGE_LIMIT` reroute: the Pro-plan gate needs `claude_subscription_type`, which returns an empty string when the keychain is locked or absent (unknown plan is then treated as non-Pro), and `bin/llm-limitsd` cannot apply that gate at all because it never reads the keychain — its shadow projection gates `fable` on `general` only. | producer: `llm-limits.sh` Claude account projection; shadow producer: `bin/llm-limitsd` `_rotation`; permissive fallback: `bin/worker-pick` |
| p | Reserved profile names | the same set in both guards, so a name that cannot be a profile cannot be offered as a switch target either: `help add enable disable remove use accounts status st profile p run warm token-upkeep`, plus `main` and any name starting with `.` or containing `/` | `bin/claudeb` `reserved_name` (with `main` checked separately by `add_account`); `bin/claude-chat-switch` `is_reserved` |
| q | Worker-pool membership | one mechanism for all three vendors, so a toggle means the same thing everywhere: the excluded names live one per line in `<profiles-dir>/.<tool>/disabled` (`.claudeb`, `.codexb`, `.geminib`), an absent file means everything is in, and the dot-directory keeps the file outside the profile enumerators' `*` glob. Read and written only through `share/worker-pool.sh`; exclusion applies to automatic selection only, never to a directly named account, including a `claudeb_profile`, `codex_profile`, or `gemini_profile` pin. Two rules the helper itself enforces: a file that exists but cannot be read means "everything is out" for readers and is never rewritten by writers. The last-member refusal lives one level up, in each vendor's `disable` verb, so a caller using the helper directly can still empty a pool | `share/worker-pool.sh`; `bin/claudeb`, `bin/codexb`, `bin/geminib` (`is_disabled`/`set_disabled`, `enable`/`disable`); `llm-limits.sh` (`enabled` per account, `ROT off`); `bin/worker-pick` (excluded from every vendor's automatic eligible set but not its pin resolution); `hammerspoon/llm-limits.lua` ("In worker pool" checkbox) |
| r | Claude leg selection announcement | the stderr literal `claudeb: worker-pick selected <name>` is a parsed contract, not free prose: claudeb prints it on every routed headless run, `ask_claude.sh` seds it into the audit row's `account` field, and the legs test stub reproduces it byte-identically | `bin/claudeb` headless routing announcement; `ask_claude.sh` audit account extraction; `tests/test_legs_routing.sh` claudeb stub |
| s | User-entry refresh classification | `needs_user_entry:true` is the structured marker for a refresh outcome that requires human account entry; a vendor error carries it only when every `"; "`-joined entry has that class, and the affected account carries it independently. Every composite cause, including multiple Claude auth failures, uses `"; "` between entries; individual stale-cause text must never contain that separator | producer and classifier `llm-limits.sh`; consumer `hammerspoon/llm-limits.lua`; guards `tests/test_llm_limits.sh`, `tests/e2e_surfaces.sh`, and `tests/test_consistency.sh` |
| t | Review receipt path and schema | `<state_dir>/receipts/<repoName>__<repoHash>.json`, directly under `receipts`, where `repoName` is the basename returned by the repository identity rule and `repoHash` is the first 8 lowercase hex characters of SHA-1 over the canonical full repository path; one JSON object with string fields `repo`, `tree`, `commit`, `run_id`, and `ts`, non-negative integer `errored`, an optional positive integer `panel` naming how many cells the run launched (absent on a manual stamp and on receipts written before it existed), and `tree` is the reviewed commit's Git tree object | writer and suggest reader `bin/review-bench`; statusline reader `bin/statusline.sh` |
| u | Late review threshold | `3` × the base cell's recorded median duration, with a `120`s (`120000`ms) floor | writer/reporting `bin/review-bench`; reader/coloring `bin/statusline.sh`; live-progress prose `docs/statusline-contract.md` |
| v | Account data age | `as_of` is the oldest valid timestamp among `five_hour`, `weekly`, and `fable` windows whose `used_pct` is numeric; `stale_seconds` is its non-negative age. Absent and null-valued windows do not participate, and an account with no data-carrying window has neither field. Vendor aggregate age applies the same rule to its hoisted windows. Metadata with separate freshness retains its own timestamp: Codex reset credits use their capture time, shadow rotation uses cache `fetched_at`, and shadow auth uses `checked_at` or the newest data-bearing window. | primary producer `llm-limits.sh` `data_as_of`/`set_data_age`; shadow producer `bin/llm-limitsd` `_project_account`; shadow bridge `bin/llm-limitsd-shadow-feed`; independent routing freshness `bin/worker-pick` `account_as_of`; consumers `llm-limits.sh` table/plain renderers and `hammerspoon/llm-limits.lua` |

# Shared invariants

Some values are duplicated across scripts written in different languages (bash,
jq, Lua, prose) because each implementation is independent — no shared library
spans `bin/claudeb`, `bin/statusline.sh`, `bin/worker-pick`, `llm-limits.sh`, the
Hammerspoon renderer, and the docs. When such a value drifts in one place, the
system misbehaves silently. `tests/test_consistency.sh` re-extracts each value
from the live files and fails if any site disagrees with the canonical value
below. This table is the canonical source; the test names it in every failure.

| ah | The statusline speaks the gate's verdict | one question, three implementations in a row, and a word renamed on any of them goes silent rather than loud. `review-bench debt --repo <top> [--session <sid>] [--paths <p>...]` prints exactly one line and always exits `0`: `none`, `debt <n> mine|other|unknown [<owned>] [locked]`, or `timed-out <run-id>`; `--list` prints the debt paths themselves instead of that line. The owner word is the third field and the only one a reader switches on: `mine` iff the asking session owns at least one debt path, `other` where it owns none, and `unknown` where no session was named at all, since a reader that computed no ownership must not assert one. `<owned>` follows `mine` alone and only where the session owns a STRICT subset, so a chat owning one path of ten no longer reads the same as one owning all ten; `locked` stays last, and nothing may parse positionally past the owner word. `timed-out` outranks the debt underneath it but never an empty repository: over content every artifact settles, the answer is `none` and the kill is history, or one dead review would hold a red statusline no artifact could ever clear. `debt --split` answers the same question for a machine, in DIFF LINES and in one line of its own: `split <own> <foreign> <orphaned>`, the lines between each debt path's covering artifact and the content standing there now — counted by `diff_numstat`, the differ the review target header prints `N file(s) · M line(s)` with, over the two contents as files, since working-tree bytes are in no object store and hashing them into one would make a render write into the repository it is reading. A path no artifact holds counts whole and a held path that is gone counts what it lost, both falling out of one side being empty, and a recorded blob this store cannot read is the first of those — the same absence `debt_snapshot_commit` drops from its base. A path this repository's attributes take out of diffing (`-diff`) counts the lines the header gives it, which is none: the comparison below is of two files OUTSIDE the repository, which no `.gitattributes` pattern can name. `<own>` folds the asking chat's journal entries and its own runs exactly as the owner word does; `<orphaned>` is the debt of paths NO journal entry names and no run record claims, separated because it belongs to nobody and counted as the asker's it reports another chat's work as theirs to answer for. The counts are cached at `<state dir>/debt-lines.json` keyed by the two contents ACTUALLY compared and by nothing else — never by a run id, which moves while the content does not; never by a sha read before the bytes were, which the file may have moved past since; and never with the sha of a blob this checkout could not produce, or the number measured without it would answer for the checkout that holds it, the file being one machine's and not one repository's. The attribute case above is for that reason not cached at all. Fresh measurements are written out in batches rather than at the end alone, or a first pass killed by the gate's timeout persists nothing and the cache never warms. So the statusline's ~3s budget survives a repository whose debt is hundreds of paths. `review-flow-gate.sh verdict <repo> [session]` is the only translator of those into a statusline line — `off`, `bright rev <own>`, `dim rev <foreign>`, or `split rev <own>/<foreign>` when both stand — and it asks about the whole repository with no paths, since debt outlives the commit that landed it.

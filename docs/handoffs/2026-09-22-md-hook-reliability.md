# Hand-off: an instruction-file hook that fires more reliably

From the chat that landed the grok-4.7 rows on 2026-09-22, after two T2 bypass hunts — round 20260922T173322Z-1e2f504 (the MD-file hooks: `bin/instruction-write-gate.sh`, `bin/instruction-bloat-gate.sh`, `bin/instruction-watch.sh`, `share/instruction-files.sh`) and round 20260922T173335Z-804ac1a (`hammerspoon/instruction-watch.lua`, the menu and the delivery path) — and the fix pass that closed 22 of their 29 items with code and a test, 6 in code alone, left 3 open by design. Full text: `review-bench findings <round-id>`. This file is what the design still cannot promise, ranked by how a change would slip past Egor's menu today, and the shape of the hook that would not let it.

## What the rounds proved about the design, not the code

1. **Coverage is an enumeration, and every enumeration has an edge.** `instruction_guarded_paths` is one pruned `find` over `~/.claude` plus the current repository's `CLAUDE.md`/`CLAUDE.local.md`/`SKILL.md`/`.claude/**/*.md`, plus ten ranked project files from tokenmap. A file outside that list — the eleventh-ranked repository, a repository the chat is not standing in, a markdown file Claude Code will load tomorrow from a directory the list does not know — is written unseen and never reported. Each hunt found one more directory (`hooks/`, `skills/foo/SKILL.md`, `review-debt-ignore`); the next hunt will find another.
2. **The state the hooks trust is state the LLM can write.** Baselines (`session-*.tsv`), alert markers, receipts, `ranked.txt`, the retry stamps of the bloat and write gates all live under `~/.cache/claude-instruction-watch` and `~/.claude`, in the same process's reach as the file it is guarding. A missing baseline is now an event rather than a silent snapshot and a pre-existing stamp directory is still accepted (open item), but the class of attack — write the evidence, then write the file — is closed only per state file, never as a whole.
3. **The tripwire sees a change only when a hook runs.** PostToolUse fires for the session's own tool calls. A subagent's Bash, a background process the tool call started (`nohup`, `setsid`, a `&` job the scanner cannot follow into the future), a launchd/cron job, a worker's own session, an editor Egor opened, are seen at the next check of SOME session, attributed to whatever call that session happened to run, and reverted or not by that call's shape. The parse of "did this call write the file" is a heuristic over shell text and will always have the ten holes the scanner rounds keep closing (interpreters, heredocs into shells, `$'…'`, backslashes, aliases).
4. **Bounds are silent drops.** The journal keeps 200 records (`INSTRUCTION_WATCH_JOURNAL_MAX`) and the Lua tail loads 200 too; a burst past that between pumps truncates before delivery (open item, Lua:113). Twelve rows are rendered. Stale records over six hours are receipted without an alert. Baselines older than seven days are swept (`-mtime +7` at watch.sh:469), the reference one now excepted, so a live week-old session can lose its own and fall to the "newest other" comparison.
5. **Two doors, two readings of the same call.** The gate judges the PreToolUse SHAPE (rows of `instruction_write_targets`), the tripwire judges POST bytes; `own_write`, the marker key, the revert decision are each a separate parse of the same command text. The six items fixed in code without a test (4, 15, 20, 23, 26, 28) are all in this seam: `git apply`/`stash pop` are not copy verbs, `bash -c "$(cat <<EOF)"` has no assertion, `tokenize`'s quoted-interpreter rule is weakly tested, the Lua `INSTRUCTION_WATCH_STATE` read has none, the unknown-session baseline (now keyed per CLI process, `session-unknown-<ppid>`) has one, `CLAUDE.m\d` has none.

## The shape that would be reliable

The reliable version does not read shell text at all and does not enumerate. It watches the FILES.

- **Kernel evidence instead of tool-call evidence.** One long-lived watcher (Hammerspoon `hs.pathwatcher` on `~/.claude`, on each registered repository's `.claude/`, `CLAUDE*.md`, `SKILL.md`; or an FSEvents/`fswatch` LaunchAgent under `~/.local/libexec/<name>` per the repo's Login Items rule) receives every write whoever made it — a subagent, a worker, launchd, Egor's editor — and hashes on the event. No baseline the LLM can delete: the watcher's previous hash lives in its own process and in a journal outside `$HOME`'s LLM-writable tree (a root-owned or `chflags uchg` directory, or the Hammerspoon process's memory plus a receipt file it alone writes).
- **Attribution by time, not by parse.** The watcher stamps the change; the sessions' hook journal (which session ran which tool call when, already written by the workdir hooks' place journal) answers "which chat was in flight in that second". A revert decision becomes "the span holds and a session's call was in flight" instead of "this command's text names the file". The shell scanner stays for the PreToolUse DENY — a deny is cheap when wrong and the scanner's job there is the price message, not the audit — and drops out of the audit path.
- **Coverage by rule, not by list.** The watcher's set is "every `*.md` Claude Code would load": the same rule tokenmap uses to index reads (`read-rates.json` is the ground truth of what actually entered a context window), applied as a glob per registered root, with a nightly diff of the watched set against tokenmap's index so a newly loaded file becomes watched before the next session rather than after the next hunt.
- **Fail-closed at the only door that can close.** PreToolUse keeps exit 2 on any hook error. The audit path cannot fail closed — a missed event is a missed event — so its reliability is the watcher's uptime, and that is what the menu must show: a `watcher: live since …` line under `Automations ▸ Instruction files`, red when the process is gone or its heartbeat is older than its interval. A silent watcher is the one failure the current design cannot display either.
- **Bounds that alert on themselves.** A journal truncation or a receipt-without-alert becomes one row (`N changes dropped`) rather than a silent count.

## What is left open in the current code, for whoever picks this up

- Pre-creatable retry stamp directory (bloat-gate:378 `instruction_stamp_ready`, write-gate:223): an LLM can `mkdir` the stamp before the first deny and pass on the first try. The fix is a stamp the gate alone can mint (an HMAC over hash+time with a key outside `$HOME`), which is the same "state outside the LLM's reach" the watcher needs.
- 200-record journal truncation before pump (Lua:113, watch.sh trim): raise the cap or trim only records that already carry a receipt.
- Seven-day baseline sweep of a live session (watch.sh:469): sweep by the session's last hook stamp, not the file's mtime.
- Items 4, 15, 20, 23, 28 above: an assertion each, spelled with the round's exact command; item 4 also `git apply`/`stash pop` as copy verbs.

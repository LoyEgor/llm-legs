# Browser runs

What drives a browser for automation, and the Harness doctor rows that watch it.

- `worker-run browse [--enroll <account|all> [--pin <dir>] | --window <account> | --seen <token> [--account <a> | --target dia] | --canary | --json | --hide | --show | --toggle]` — Chrome is automation's browser, one profile per pool account (Local State `info_cache[dir].user_name` = the account's `.oauthAccount.emailAddress`, or a `--pin`; the registry's `chrome_profile` when macOS denies Local State, as it does a LaunchAgent's tree); Dia is Egor's and nothing launches, quits or relaunches it. The registry `~/.cache/claude-worker-runs/browse/accounts.json` (email, chrome_profile, pin, device_id, proven_at, status ok|needs-login|no-profile|proof-failed, last_error) is written only by enrollment and live proofs. `--enroll` ensures the profile's window (a `#worker-run=<dir>` marker tab: asking again never piles windows up), runs a short `claudeb --chrome` proof session and prints `ENROLL: <account> <status> <dir> <device>`; no device within `BROWSE_RECONNECT_S` (600 s) of Chrome's start or of a window this run opened is `proof-failed` "has not reconnected yet", later it is `needs-login`, which comes with a REASON to dispatch `share/briefs/claude-ext-login.md` (the supervisor never logs in). A proof is select → navigate to a token URL → `--seen <token> --account <a>` finds it in the Chrome window holding that account's marker tab (a window is one profile; Dia: its own tab list). `start` reads the brief header `BROWSER: chrome|yes|dia` like `ACCOUNT:` (a contradicting `--target` fails; `--browser` alone is Chrome), prepends the fixed preamble (registry device first, then `isLocal` entries; `BROWSER-PROVEN: <device> <account>`; JS fill with read-back else `BROWSER_CLICK_UNVERIFIED`; a sign-in or consent only Egor gives `BROWSER_OWNER_LOGIN site=`, never a repair or an account failure; anything else forbidden `HARNESS_NEEDS_REPAIR reason=`) and records `browser_target`/`browser_profile`. A codex browser run first syncs `cua_repl` and Sky like `--computer`. At delivery the supervisor appends one line per browser run to `browse/log.jsonl` (ts, run, vendor, account, profile, target, device, outcome — `missing` without an OUTCOME, `BROWSER_INTERRUPTED` when it died or a proof session timed out, `BROWSER_UNPROVEN` for a Chrome `BROWSER_OK` with no proven device — and `workaround`: since the run started: an unlisted device id, a Chrome launch of its own (the executable, never an operand), `--chrome` without `--browser`, or a script aimed at the other browser, read from the transcript). `--canary` (the doctor's schedule, ≤ once per 23 h, or by hand; skipped while a browser run is live) makes each enrolled account submit a form to a listener of its own and logs `BROWSER_OK` and refreshes `proven_at` only with the server's receipt; an account out of the claudeb worker pool (the same wall `claudeb` applies, pin included) is skipped unlaunched (`CANARY: <account> skipped — out of the worker pool`, row `CANARY_OUT_OF_POOL`), so is one `worker-pick --list --role browser` shows `walled` (`skipped — walled`, row `CANARY_WALLED`), and a session whose error result or stderr `has_limit_signature` reads as a wall logs `CANARY_WALLED` too (weather: never judged, no failure exit), a session that never reached the model (an empty answer with stderr text, or an `is_error` result with `duration_api_ms` 0, e.g. `Not logged in`) logs `CANARY_NOT_STARTED` with its first error line as `error` (Harness doctor: red), one that ran without a receipt `CANARY_NO_RECEIPT` (an account watch at once). After those legs one codex leg runs: the first `ok` codex row of the same list drives the first enrolled `ok` profile whose window opens through the Codex extension (`codex exec`, CODEX_HOME of that account, `cua_repl` and Sky checked first, effort low), judged by the same receipt; it prints `CANARY: codex/<account> <outcome>`, logs `vendor: codex` rows under `canary-codex-<account>-…`, keeps `browse/last-session-codex-<account>.out|.err`, skips a walled or out-of-pool codex the same way (no `ok` row: the first `walled`, else `off`/`paused` one), skips an unreadable Local State as Egor's one-time step (the Codex browser list then names no profile: `skipped — waits for Egor's macOS grant: <why>`, row `CANARY_OWNER_GRANT`, never judged), and reads a preflight failure, a list with no serving row or an empty answer with an `ERROR:` line as `CANARY_NOT_STARTED`. A browser run starts under picker role `browser` on claudeb and codex alike: `<vendor>_workers=off` and the pin never close it. `claudeb` appends `~/.local/bin` to a PATH that has no `claude` (launchd), sets an unset `USER` (claude's keychain lookup needs it), and refuses a launch naming both places when neither has `claude`. A Chrome that worker-run launches carries `CHROME_FLAGS` (no renderer backgrounding, no timer or intensive wake-up throttling: a hidden page otherwise ticks once a minute by minute 3); a running Chrome is never relaunched for them. Opening a window gives focus back to the app frontmost before, only while Chrome holds it. Chrome is hidden unless Egor turned Show Chrome on (Egor 2026-10-23: an automation Chrome nobody asked to see is never shown): every window opened is re-hidden through System Events (never AppleScript to Chrome, which unhides and activates it) unless `browse/shown` exists or a `--computer` run is live. `--show` unhides Chrome and writes `browse/shown`; `--hide` hides it, removes the file, warns when the running Chrome lacks the flags, and refuses while a `--computer` run is live; `--toggle` runs `--show` when System Events reads Chrome hidden, else `--hide`. Only these write or remove the file: it outlives every run. The canary's end and the last live Chrome run's delivery quit Chrome when no run drives it and every tab is a marker, probe or canary page (`browse_quit_idle`), so no window outlives its run. The automation menu's one top-level `Show Chrome` checkbox answers for every automation Chrome, read from the running processes (shared-invariants row `en`, whose test fails on a new launch site): Chrome whenever it runs, hidden or not (it quits once idle; the canary, enrolment and `--window` drive it outside any run, and hiding it mid-canary took the item away on 2026-10-19), and the media tools' clone `com.google.Chrome.gemini-web` (`share/gemini_web.py`) while any runs. It is checked on each open while Chrome is not hidden or a clone window's centre is on a screen; a click sets both records one way, whichever Chrome runs: `browse --show`/`--hide`, and every clone window onto the main screen or off it over AX (the clone is LSBackgroundOnly, which macOS never hides), writing or removing `~/.gemini-web/windows-shown`, which keeps `park_window` from parking any clone page while it exists and outlives every clone. Both Chromes flash at launch (measured 2026-10-23): a clone window lands at the work area's top-left whatever `--window-position` says, transparent 100–400 ms, then opaque 10–95 ms until `park_window` moves it (a window bigger than the screen, the iPad's 1344×1008, opens maximized and is un-maximized first: a move alone only un-maximized it and whole ChatGPT runs stayed on the iPad, 2026-10-24); the real Chrome unhides and activates itself for every URL handed to it (`open -g`, `open -j` and its own binary alike), all its windows on screen 450–600 ms. Egor accepts both (they tell him a run started; 2026-10-23): no machinery against them — a Hammerspoon app watcher re-hiding Chrome (0–16 ms left, reverted) and an AX park of the clone (3 of 5 caught, 50 ms menu stalls) were tried and dropped. It is not a doctor row: launchd drops a `kickstart` while the doctor is mid-run, and its 1–3 min runs outlast short browser runs.
- `bin/dia-js (--active | --url-contains <s> | --tab-id <id>) [--file <js>] [--focus]` — runs JavaScript (a file or stdin) in a tab Egor already has open in Dia and prints Dia's JSON-encoded result; `--list` prints every tab (id, front 1/0, URL, title); no match and several matches are errors naming `--list`/`--tab-id`. A Dia without `--enable-applescript-javascript` is quit, reopened with it (`open -b company.thebrowser.dia --args …`), waited on until its restored tab count holds, and the tab is found again by URL (ids change), focused and run — `RELAUNCHED: yes` plus a `WARNING:` that unsaved input may be lost, on stderr. `--relaunch` does only that; `--open` brings Dia forward and starts a closed one with the flag (`open -b … --args --enable-applescript-javascript`, no quit); `--relaunch --auto` is the Hammerspoon watcher's call (`hammerspoon/dia-flag-watch.lua`, on each Dia launch): silent for a flagged or closed Dia, skipped while `~/.cache/dia-js/watch-off` exists or within 120 s of its last relaunch (`DIA_JS_GUARD_S`), and it reopens the front tab URL (a link-click cold start) when session restore does not bring it back. A Dia still without the flag is the Harness doctor's Browser watch.
- `bin/chrome-applescript-js [status|enable] [--profile <dir>]` — `enable` refuses (`OUTCOME: CHROME_BUSY`) while `worker-run _chrome-runs` names a live run that may drive Chrome (a browser run not targeting Dia, `chrome` or `computer` runs) or a `--chrome` process lives, else quits Chrome, sets `browser.allow_javascript_apple_events` in that profile's `Preferences` (Chrome rewrites the file on exit, so only while it is quit), relaunches it on the profile and re-reads the pref (`OUTCOME: RESET_BY_CHROME` if Chrome undid it).
- Harness doctor **Browser** section — reads only `browse/accounts.json`, `browse/log.jsonl` and process arguments: one row per enrolled account (profile, status, proven age, 72 h failures by kind); `needs-login` a watch whose fix is the login brief, another non-ok status or no success in 7 days a watch whose fix is `--enroll`; a red `harness needs repair` row for a 72 h workaround, `HARNESS_NEEDS_REPAIR` or `missing`; Dia without `--enable-applescript-javascript` a watch plus a clickable `Restart Dia with AppleScript JS` row (menu flag `a`) running `bin/dia-js --relaunch` on Egor's click. A writing run starts `browse --canary` when `browse/canary.stamp` is older than 23 h. It never opens, quits or launches a browser.
